This project's Baseline target is Baseline Newly available.

Prefer native HTML and CSS over JavaScript. Fix layout issues with CSS. Do not use JavaScript to scroll, measure, or reposition elements to correct layout. The single exception is a `pe-*` behavior where the platform has no CSS path for the job: `src/behaviors/carousel-controls.js` sets `inner.scrollLeft` while panning, and only behind `@supports not selector(::scroll-button(inline-start))`. Every such exception must be stated in the module's header comment, naming what the platform is missing. A polyfill may read, never write, scroll geometry when the API it emulates exposes no observer for it: `src/polyfills/scroll-target-group.js` reads scroll offsets to choose the `:target-current` link and says so in its header. Do not add `bootstrap.js` or classList-driven UI state. Polyfills live in `src/polyfills/` and must be loaded only after feature-detecting the missing API (and only when the document uses it). Never load a polyfill unconditionally. Experimental platform features (for example `scroll-target-group` and `::scroll-button`) are in scope when a component is marked experimental in the docs.

Never put a new pseudo-element (for example `::field-content`, `::scroll-button()`, `::picker()`, `::slider-fill`) in a selector list with a selector that must work everywhere. A browser that does not know one selector in a list drops the whole rule: Chrome 148 has `appearance: base-select` but not `::field-content`, so `selectedcontent, select::field-content` lost both. `:is()` / `:where()` cannot rescue it because they do not accept pseudo-elements. Write separate rules and share declarations with a Sass mixin, not `@extend` (that regroups the selectors). The lightningcss minify warning about an unknown pseudo-element is expected; the selector passes through unchanged.

Custom elements are prefixed `pe-`, never `pep-`: `pe-alert` (`src/behaviors/alert.js`), `pe-carousel` (`src/behaviors/carousel-controls.js`, which `src/behaviors/carousel.js` imports only where `::scroll-button` is missing), `pe-focus-group` (`src/behaviors/focus-group.js`), `pe-tabs` (`src/behaviors/tabs.js`), `pe-toast` (`src/behaviors/toast.js`).

`src/behaviors/count.js` is a module, not a custom element. Load it on pages that use `<output data-controls>`. `data-controls` is a container id, with no hash — the same shape as `commandfor`. The script listens to `change` and writes how many `input[type=checkbox]` inside that node are checked. Do not add `pe-count`. Do not watch the `checked` attribute with a MutationObserver (that misses clicks and `el.checked = true`). Visible checkboxes can use a CSS counter instead; a closed popover cannot.

`src/behaviors/step.js` is a module, not a custom element. Load it on pages that use `command="--step-up"` or `--step-down`. `commandfor` is the input id, with no hash — the same id as `label[for]`. The `command` event does not bubble, so the listener is on `document` in the capture phase. The module calls `stepUp()` / `stepDown()`, then fires `input` and `change` (those methods fire no events). Do not add `pe-step`. Types with `step` work (`number`, `range`, `date`, `month`, `week`, `time`, `datetime-local`). `step="any"` throws and is ignored.

`src/behaviors/range-group.js` is a module, not a custom element. Load it on pages that use `.form-range-group` (or `data-pe="range-group"` without Bootstrap classes). It clamps stacked `input[type=range]` so thumbs do not cross (overlap is allowed) and writes `--pe-range-lower` / `--pe-range-upper` on the group for the CSS fill. It also writes `output[for~=id]`. `data-range-group="off"` on the group skips the module; the CSS stack stays. Do not add `pe-range-group`. Do not rewrite `min` / `max` on the inputs (that breaks the shared track). There is no CSS path from a live range value; `<rangegroup>` and `::slider-segment` have not shipped. Without the module the inputs still work; thumbs can cross and there is no fill.

`src/data/components.js` is the component inventory: the required or optional `pe-*` element, polyfills, Baseline status, the Bootstrap hooks each component replaces, and the markup that is not supported (`avoid`). `nav` is the docs sidebar group (`components`, `recipes`, or `forms`). Composed recipes are `recipes`, not a component. Read it before writing component markup, and update it when a component changes. The docs pages and `/components.json` are generated from it, so do not restate its contents in a page.

`src/patterns/<id>.html` and optional `<id>.css` are the neutral contract: markup with no classes and no `data-bs-*`, hooked by `data-pe="<id>"`, plus only the mechanics CSS those hooks need (state selectors, top-layer transitions, anchors, `@supports` fallbacks, reduced motion). Custom properties take defaults inline (`var(--pe-duration, .15s)`). Style `::backdrop` only in modal and offcanvas. Pattern CSS uses native nesting. Nest under one selector, not a list: `&` takes the highest specificity in the list. Declarations come before nested rules, each nested selector starts with `&`, and `@keyframes` stays at the top level. An at-rule inside a pseudo-element rule holds no bare declarations, because before `CSSNestedDeclarations` (Chrome 130, Firefox 132, Safari 18.2) they were wrapped in `&`, which cannot match a pseudo-element; put the at-rule around the rule instead (`@starting-style { &:open::backdrop { … } }`). An id without a pattern sets `patternless` in `src/data/components.js` with the reason. `src/lib/patterns.js` reads the files; the contract ships them as `pattern`, `/llms-full.txt` shows them before the Bootstrap example, and `/patterns/<id>` renders each one without Bootstrap CSS. A pattern must not contain a triple backtick or a `<script>` tag; the contract lists scripts.

`src/lib/hash.js` gives each component a contract `hash` over its pattern, required script source, polyfills, `avoid`, and `a11y`. `src/data/contract-hashes.json` is the snapshot at the last release. When a hash moves, add a `changes` entry in `src/data/components.js` with a `sinceVersion` newer than the snapshot (`breaking` needs a `migration`); `tests/versioning.test.js` fails until you do. Run `npm run contract:hashes` when you cut a release, not on every change. Bump `hashVersion` only when the hash input changes shape. Agents record copied patterns in `bootstrap-html.lock.json` (the contract's `manifest`) and must not overwrite local files without asking.

`src/data/examples.js` holds one canonical markup example per inventory id, in the Bootstrap theme. The component page renders it with `code={examples.<id>}`, and `src/lib/contract.js` ships it as `example` in `/components.json` and the packaged `dist/components.json`. `src/lib/llms.js` puts the same example in an `html` code block in `/llms-full.txt` and `dist/llms-full.txt`, so an example must not contain a triple backtick. Pick markup that works in every supported browser, and include the `pe-*` element and its module when the component requires one. Edit the example there, not in the page.

Docs `.astro` templates use `compressHTML: true` in `astro.config.mjs`. Astro 7’s default JSX compact would glue a wrapped `on <a>` into `onComposed`. Wrap prose onto `<code>`, `<a>`, `<em>`, or `<strong>` with the preceding word on its own line; the newline is the space. Do not switch `compressHTML` back to `"jsx"`.

`dist/js/polyfills/` and `dist/js/behaviors/` are generated by `npm run js` (`scripts/build-js.js`, part of `build` and `prepare`): one minified file per module in `src/polyfills/` and `src/behaviors/`, no bundling, so the loader's relative `import()` still fetches siblings on demand. Edit `src/`. The copies are not bundled, so a module may import only a sibling by relative path, never a package. Plain-HTML examples and code samples load `dist/js/behaviors/<name>.js`; bundlers import `bootstrap-html/behaviors/<name>` (the source). The docs layouts load the loader with `<script is:inline type="module" src={polyfillLoaderPath()}>`, and `/patterns/*` loads behaviors with `behaviorPath(name)`; do not import either from a processed `<script>`, because Vite then adds its preload helper. Component pages may still import behaviors in a processed `<script>`. A legal comment (`/*! … */`) is the only comment that survives minification; keep the one in `interestfor.js`.
